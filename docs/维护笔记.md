# 维护笔记

改动这个项目**之前**该知道的事：项目沿革、硬约束、设计决策的理由、踩过的坑。

---

## 一、项目沿革：为什么会有这次重建

站点 2015 年建，原用 **Hexo 3.9.0 + NexT 主题**，最后一次部署停在 **2021-01-06**。

**出问题的地方**：GitHub 仓库里只有 `hexo deploy` 推上去的**渲染产物**，源码目录
`~/user_blog` 后来从本机消失了 —— **源码丢了，只剩渲染结果**。

2026-09-17 从渲染 HTML 反推 Markdown，重建为 Astro。108 篇全部提取，零丢失。

**这次的结构保证不会再重演**：文章以纯 Markdown 存仓库，GitHub Actions 直接构建
发布到 Pages，**构建产物不提交**。仓库里永远只有源码。

---

## 二、三条硬约束

改动前务必确认没有违反：

### 1. URL 必须与旧站逐字一致

`/<年>/<月>/<日>/<slug>/`。旧外链与搜索引擎收录都指向这个结构，**改了就是全站死链**。
实现见 `src/pages/[year]/[month]/[day]/[slug].astro`。

### 2. 归档文章必须仍可访问

`archived: true` 的 27 篇只是不进列表/归档页/sitemap。路由的 `getStaticPaths`
**必须用 `getPosts(true)`** 把它们包含进来，否则旧链接 404。

### 3. 仓库只放源码

构建产物不入库。这是对「源码丢失」事故的结构性修复，别为了方便把 `dist/` 提交进去。

## 三、设计决策及其理由

### 导航只有 4 项

`首页 / 归档 / 标签 / 关于`。砍掉 `Sitemap`（给爬虫的 XML，不该占给人看的位）
与 `Categories`（与 Tags 严重重叠：分类 6 组、标签 67 个，算法/java/C 两边都有）。
详见 [写作与发布](写作与发布.md#-改导航前必读)。

### 首页没有 H1 是有意的

首页是入口，形态与其他页不同是常见做法。关键是**它和内页共用同一套容器语言**
（纸感底色、字体和细分隔线），所以差异读起来是设计而非遗漏。
**别给它加标题。**

### 所有内页必须套 `.page-panel`

归档 / 标签 / 分类 / 关于 / 文章正文一律用这个语义容器。2026-10-18 纸感方案下它为透明容器，
与首页的编辑式条目共享纸张底色；不再依赖带阴影的卡片外框。**新增内页时别忘套。**

### `.page__main` 的 `min-height: 100vh` 不能删

否则短页面（分类/标签）的页脚会紧贴内容悬在页面中间，下方留一大片空白，
看起来像渲染坏了。

### 2026-10-18：纸感手记与宽正文

用户先确认 A 布局，再选择「纸感手记」外观。保留四项导航、现有页面类型和所有文章 URL。

- 页面采用居中两栏，正文上限 880px，右侧栏 240px；不在正文容器里再切出一列目录。1440px 与 1920px 窗口的目标正文宽度均为 880px，避免旧布局在宽屏下仍只有约 534px。
- 右侧栏在文章页切换「文章目录 / 关于作者」；无足够标题时直接展示作者。1100px 及以下改用正文前默认折叠的目录，避免先翻过整页目录才能开始阅读。
- 暖白 / 深墨底色、宋体标题、无衬线正文与橙色强调；首页用细分隔线组织文章，不添加首页 H1。全站使用本地字体和 `Icon.astro`，不依赖远程图标字体。
- 代码高亮同时生成亮暗色主题；搜索关闭按钮在面板内部，打开时锁住背景交互、约束 Tab 焦点，关闭后恢复原焦点。
- 验收先看真实本地页面。方案原型在工作区 `work/blog-design/`，不是博客源码或正式内容，不提交到博客仓库。

本地验收（2026-10-18）：构建通过；111 篇既有文章内容与改版前一致，111 条文章链接均返回 200，含 27 篇归档文章；首页、归档、标签、分类、关于、404、分页、RSS 与 sitemap 入口正常。320 / 390 / 768 / 1024 / 1440 / 1920px 六种窗口无页面横向溢出；桌面正文宽 880px、390px 手机正文宽 350px。桌面和手机目录跳转与高亮、手机目录收起、代码复制、作者页签与键盘切换、亮暗主题、真实搜索结果、焦点约束和关闭后焦点恢复均已检查。用户已审核本地效果并确认上线；实际部署结果以对应提交的 GitHub Actions 和线上页面检查为准。

### 2026-10-18：作者简介排版

用户确认采用统一左对齐的紧凑排版：头像与名字横排，简介、联系与订阅、单行统计依次排列；沿用现有署名与简介，不添加未经确认的身份或经历。统计继续包含归档文章，字号与联系方式分层，取消原有大数字和上下双分隔线。友情链接作为独立分区；文章页的作者侧栏通过 `Sidebar showLinks={false}` 隐藏友情链接（包括无目录的文章），首页及其分页也按用户后续要求隐藏友情链接，归档、标签等其他页面保留。维持侧栏宽度、纸感配色及既有窄屏布局。

本地验证：构建与搜索索引生成通过；检查首页及文章页作者面板的亮暗模式、页签切换与 320 / 390px 窄屏，未见页面横向溢出。1440px 窗口统计区域约 30px 高，文章页作者面板约 223px 高。截图保存在工作区 `work/blog-design/profile-review/`；验证后停止开发服务并关闭自动化浏览器。

## 四、踩过的坑

### 提取正文不能用正则

`articleBody` 是嵌套 div，正则必然出错。实测同一篇用正则抽出 0 字、
用 HTML 解析器抽出 5995 字。`scripts/extract-hexo.py` 用 `html.parser`
追踪 div 嵌套深度，并内置**零丢失断言**（任一篇异常即中止）——
静默丢文章是这类迁移最严重的失败模式。

### 文件名里的 `#`

旧站有一篇 slug 含 `#define`。Astro 会把 `#` 编码进目录名（`%23define`），
而服务器解析 URL 时把 `%23` 解码回 `#` → 对不上 → 404。
故有构建后处理 `scripts/fix-encoded-dirs.mjs` 把目录名改回字面 `#`。

新增文章时，`npm run new` 会自动清洗文件名，但**保留 frontmatter 的 slug**。

### Pagefind 1.x 的 `pagefind-ui.js` 是 IIFE，不是 ES 模块

文件末尾执行 `window.PagefindUI = ...`，**一个 `export` 都没有**。
用 `import()` 会**静默拿到空对象（无报错）**，搜索打不开还查不出原因。
必须用 `<script>` 标签加载经典脚本。

另外 Vite 会因为这个文件「构建后才生成」而在构建期报 UNRESOLVED_IMPORT，
所以也不能静态 import。

### 目录高亮不能拿 `a.hash` 直接比元素 id

`a.hash` 是**百分号编码**的（中文标题编成 `#%E6%95%B0…`），元素 id 是解码后的中文，
直接比**永远不相等**。两侧都 `decodeURIComponent` 后再比。

### 手写百分号编码极易出错

排查「链接失效」时，我多次在 shell 里手写 URL 漏字导致误判。
**一律用 `urllib.parse.quote()` 构造，别手写。**

### `npm run preview` 不解码中文 URL

Astro 自带的简易静态服务器会有中文 URL 404，**不是站点问题**。
本地验证用 `npm run dev`，或用 `python3 -m http.server` 起 `dist/`。

### 环境障碍（2026-09-17 当天）

| 问题 | 处置 |
|---|---|
| `git clone` 只有 15–68 KB/s | 改从 GitHub Pages 的 Fastly CDN 拉，108 篇 **74 秒**完成 |
| `registry.npmjs.org` 不可达 | `.npmrc` 指向 npmmirror |
| Astro 7 要 Node ≥22，系统 Node 20 上挂着别的工具 | 另装 keg-only 的 `node@22`，**系统 Node 未动** |
| `brew install` 卡在 auto-update | 加 `HOMEBREW_NO_AUTO_UPDATE=1` |

### 旧站本就有 7 张坏图

含一张文件名写成中文全角逗号 `2，png`（原作者笔误），在旧站上就是 404。
按**忠实原状**原则保留了引用，未擅自删改。见 `scripts/extract-hexo.py`。

## 五、常用排查

```bash
# 构建（含路径修正与搜索索引）
npm run build

# 全量验证文章 URL 是否可达
#   —— 从 Markdown frontmatter 取 slug 构造 URL，别手写百分号编码
python3 - <<'PY'
import re, urllib.parse, urllib.request
from pathlib import Path
from concurrent.futures import ThreadPoolExecutor
B='http://localhost:4321'
u=[]
for md in Path('src/content/posts').glob('*.md'):
    t=md.read_text(encoding='utf-8')
    d=re.search(r'^date: (\d{4})-(\d{2})-(\d{2})', t, re.M)
    s=re.search(r'^slug: "(.*)"$', t, re.M)
    if d and s: u.append(B+'/'+urllib.parse.quote(f'{d.group(1)}/{d.group(2)}/{d.group(3)}/{s.group(1)}/'))
def c(x):
    try: return urllib.request.urlopen(x,timeout=20).status
    except Exception as e: return getattr(e,'code','ERR')
with ThreadPoolExecutor(max_workers=12) as ex:
    bad=[x for x,st in zip(u,ex.map(c,u)) if st!=200]
print(f'{len(u)-len(bad)}/{len(u)} 可达')
for x in bad: print('  ✗', urllib.parse.unquote(x))
PY
```

> 注意：少数 `ERR` 是网络波动，**重试一次**再判定。曾多次把波动误判成死链。
